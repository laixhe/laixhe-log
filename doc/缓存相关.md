# 缓存相关

## 缓存雪崩

缓存在同一时刻全部失效，造成瞬时 DB 请求量大、压力骤增，引起雪崩。缓存雪崩通常因为缓存服务器宕机、缓存的 key 设置了相同的过期时间等引起。

**常见解决方案：**

- 缓存过期时间加随机值，避免同一时刻集中失效。
- 使用高可用缓存集群，避免单点宕机。
- 限流、降级，保护后端 DB。

## 缓存击穿

一个存在的 key，在缓存过期的一刻，同时有大量的请求，这些请求都会击穿到 DB，造成瞬时 DB 请求量大、压力骤增。

**常见解决方案：**

- 热点 key 设置永不过期（或逻辑过期 + 后台异步刷新）。
- 加互斥锁（分布式锁），同一时刻只允许一个请求回源 DB 并重建缓存。

## 缓存穿透

查询一个不存在的数据，因为不存在则不会写到缓存中，所以每次都会去请求 DB，如果瞬间流量过大，穿透到 DB，导致宕机。

**常见解决方案：**

- 布隆过滤器（Bloom Filter）：在请求到 DB 前先过滤掉一定不存在的数据。
- 缓存空值：对查询不到的 key 也缓存一个空值（或短过期标记），避免每次都打 DB。
- 参数校验：对明显非法的请求参数直接拦截。
